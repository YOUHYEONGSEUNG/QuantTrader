# 백테스트 가이드와 설정값 설명

`TQ_Strategy`를 NinjaTrader의 Strategy Analyzer로 백테스트하는 절차와, 설정창에 보이는 값이 각각 무엇을 뜻하는지 정리한 문서입니다. 규칙 자체는 `docs/spec.md`, 바뀐 이력은 `docs/changelog.md`에 있습니다.

## 1. 돌리기 전에 확인할 것

| 확인 | 이유 |
| --- | --- |
| Visual Studio를 닫는다 | 켜져 있으면 `obj` 폴더가 생겨 컴파일이 깨진다 |
| NinjaScript Editor에서 F5를 눌러 에러가 없다 | 에러가 있으면 예전 코드로 백테스트가 돈다 |
| Connections에서 Playback 연결을 끊는다 | Playback에 연결된 동안에는 Run 버튼이 눌리지 않는다 |

## 2. 백테스트 절차

1. Control Center → New → **Strategy Analyzer**.
2. 종류는 **Backtest**, 전략은 **TQ_Strategy**.
3. **Instrument**: `MNQ DEC26`. 직접 입력하고 Enter.
4. **Data Series**: Type은 Minute, Value는 **3**. 여기가 진입 봉이다 (4장 참고).
5. **기간 (From / To)**: To는 마지막으로 보고 싶은 저녁의 **이틀 뒤 날짜**로 넣는다. 대회 시간이 자정을 넘기 때문이다. 예: 10/5 저녁까지 보려면 To = 10/7.
6. 아래 설정값을 확인하고 **Run**.
7. 결과에서 **Summary**(합계)와 **Trades**(거래 목록)를 본다.
8. Trades 탭에서 우클릭 → **Export**로 저장한다. 문서 폴더에 저장하고 Claude에게 "결과 봐줘"라고 하면 거래 단위로 분석한다.

### 지켜야 할 것

- **한 번에 하나만 바꾼다.** 두 개를 같이 바꾸면 어느 쪽 효과인지 알 수 없다.
- **바꾸기 전에 기본값으로 한 번 돌려 기준을 잡는다.** 같은 기간, 같은 봉으로 비교한다.
- **지금 가진 데이터는 9/29~10/5뿐이다.** 기간을 그보다 넓게 넣어도 결과는 같다.
- **결과가 좋아졌다고 바로 믿지 않는다.** 진입이 10번도 안 되는 표본이다.

## 3. 결과 읽는 법

NinjaTrader는 분할 진입 한 덩어리를 거래 1건으로 센다. 30계약을 6 / 12 / 12로 나눠 들어가면 3건이다. 같은 시각에 들어간 건들을 묶어 "진입 1번"으로 읽는다.

| Trades의 Entry name | 뜻 |
| --- | --- |
| UpL1, UpL2, UpL3 | 상승추세 매수 (주력). 6 / 12 / 12계약 |
| UpS1, UpS2 | 상승추세 매도 (역추세). 15 / 15계약 |
| DnL1, DnL2 | 하락추세 매수 (역추세). 10 / 20계약 |
| DnS1, DnS2, DnS3 | 하락추세 매도 (주력). 10 / 10 / 10계약 |
| SideL1, SideL2 | 횡보 매수. 15 / 15계약 |
| SideS1, SideS2 | 횡보 매도. 15 / 15계약 |

| Trades의 Exit name | 뜻 |
| --- | --- |
| x로 시작 (예: xSideL1) | 분할 익절 |
| Stop loss | 손절. 체결가가 진입가와 같으면 본절 |
| Sell / Buy to cover | 나머지 전량 청산 (청산 조건 충족 또는 00:27 종료 청산) |

| 열 | 뜻 |
| --- | --- |
| MAE | 보유 중 가장 불리했던 폭 (달러) |
| MFE | 보유 중 가장 유리했던 폭 (달러) |
| Bars | 보유한 봉 수 |

MNQ는 1포인트가 계약당 2달러다. 30계약이면 1포인트에 60달러.

## 4. 진입 봉 (Data Series)

전략은 여기서 고른 봉을 그대로 진입 봉으로 쓴다. 코드에 고정된 것은 추세 판단용 10분봉뿐이다.

| | 3분봉 (명세) | 1분봉 (실험) |
| --- | --- | --- |
| 밴드 중심선 EMA 26봉 | 78분 | 26분 |
| ATR 14봉 | 42분 | 14분 |
| 전저점·전고점 5봉 | 15분 | 5분 |
| 반전 대기 4봉 | 12분 | 4분 |
| 추세 판단 | 10분봉 | 10분봉 (같음) |

봉 개수는 같고 시간이 줄어드므로, 1분봉은 같은 전략의 빠른 버전이 아니라 훨씬 짧은 움직임을 보는 다른 전략이다. 명세는 3분봉이다.

| **SideRestBand** | 3 | 횡보 세트 A의 나머지 청산 밴드. 3이면 명세대로 ±3배 터치, 2·1이면 ±2배·±1배, 0이면 중심선. 1차 익절 전에 이 밴드에 닿으면 전량 청산되는 것도 같이 바뀐다 | 2, 1. 나머지 수량이 본절 0으로 끝나는 거래가 줄어드는지 |
| **SideRestNarrowTime** | 223000 | `SideRestBand`를 이 시각부터 적용한다. 그 전에는 3배. 기본값이면 대회 시작부터 적용 | 230000처럼 장 시작 뒤 일정 시간이 지난 다음부터만 좁히기 |

추세(레짐)가 늦게 바뀌는 문제를 보는 옵션은 아래 셋이다. 추세는 "정배열·역배열(이동평균) → `FastTrendBars` → 고점·저점 규칙 → 횡보" 순서로 판정한다.

| 설정값 | 기본 | 뜻 | 볼 것 |
| --- | --- | --- | --- |
| **RegimeBarMinutes** | 10 | 추세를 판단하는 봉. 10이면 10분봉(명세), 3이면 3분봉. 이동평균 기간·연속 봉 수·비교 구간은 모두 이 봉 기준으로 세므로, 3으로 바꾸면 같은 숫자가 3.3배 짧은 시간이 된다 | 3 + 이동평균 20 / 60 / 120(1 / 3 / 6시간), 3 + 6 / 18 / 36(18 / 54 / 108분). 추세가 얼마나 자주 바뀌는지를 배경색과 로그의 "3분봉 마감 레짐" 줄로 본다 |
| **Rule12Bars** | 3 (명세 5) | 고점·저점 규칙의 비교 구간. 10분봉 최근 N봉과 그 전 N봉을 비교한다. 5면 최근 50분과 그 전 50분 | 3. 전환을 20분쯤 빨리 인식하지만 잡음에 더 자주 바뀐다 |
| **Rule12PriceFilter** | 켬 (명세에 없음) | 켜면 고점·저점 규칙을 10분봉 종가가 20선의 맞는 쪽에 있을 때만 인정한다. 가격이 20선 위로 올라왔으면 고점·저점이 아직 낮아도 하락추세로 보지 않는다(횡보가 된다) | 반등이 시작됐는데 하락추세 규칙이 적용되던 구간이 줄어드는지 |
| **FastTrendBars** | 2 (명세에 없음) | 10분봉 종가가 N봉 연속 20선 위에서 마감하면 정배열을 기다리지 않고 상승추세, 연속 아래면 하락추세. 0이면 사용 안 함 | 2, 3. 가장 빨리 바뀐다. 대신 상승추세 중 깊은 눌림에서 N봉 연속 20선 아래면 하락추세로 뒤집힌다 |

이미 있던 `RegimeFast / RegimeMid / RegimeSlow`를 줄이는 것(예: 6 / 18 / 36)도 같은 문제의 해결책 후보다. 차트 배경색(`ShowStatus`)으로 옵션별 추세 구간을 눈으로 비교할 수 있다.

순수하게 ATR만으로 손절하려면 `StopPercent`를 0으로 두고 `MinStopAtr`에 배수를 넣는다. 손절가가 진입가에서 정확히 그 배수만큼 떨어진 곳이 된다.

1분봉 실험과 역추세 끄기는 옵션이 이미 있다. 1분봉은 차트(또는 Strategy Analyzer)의 봉 종류를 1분으로 바꾸면 되고, 역추세는 `UseCounterTrend`를 끈다.

## 7. 더 긴 데이터 받기

지금은 Connections에 Playback뿐이라 과거 데이터를 자동으로 받지 못한다. 아래 방법은 시도해 볼 만하지만 된다는 확인은 아직 없다.

1. Connections → Playback Connection에 연결한다.
2. New → Chart에서 `MNQ SEP26`(9월물), Minute 3, 기간을 6/15~9/14로 직접 지정해 연다.
3. 봉이 그려지면 데이터가 받아진 것이다. Playback 연결을 끊고 Strategy Analyzer에서 9월물로 돌린다.

9월물이 안 받아지면 같은 방법으로 `MNQ DEC26`을 더 긴 기간으로 열어 본다.

## 8. 자주 겪는 문제

| 증상 | 원인과 해결 |
| --- | --- |
| Run 버튼이 눌리지 않는다 | Playback에 연결돼 있다. 연결을 끊는다. 종목이 비어 있어도 안 눌린다 |
| 거래가 0건이다 | 그 기간의 데이터가 없다. 종목과 기간을 확인한다 |
| 결과가 지난번과 전혀 다르다 | Data Series의 Value(1인지 3인지), 기간의 To 날짜를 확인한다 |
| `TargetFrameworkAttribute` 중복 에러 | Visual Studio가 `obj` 폴더를 만들었다. 폴더를 지우고 Visual Studio를 닫는다 |
| 설정값을 바꿨는데 차트의 지표가 그대로다 | 차트에 올려둔 지표는 예전 설정을 기억한다. 지웠다가 다시 올린다 |
