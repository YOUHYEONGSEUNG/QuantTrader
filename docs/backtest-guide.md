# 백테스트 가이드와 설정값 설명

`TQ_Strategy`를 NinjaTrader의 Strategy Analyzer로 백테스트하는 절차와, 설정창에 보이는 값이 각각 무엇을 뜻하는지 정리한 문서입니다. 규칙 자체는 `docs/spec.md`, 바뀐 이력은 `docs/changelog.md`에 있습니다.

## 1. 돌리기 전에 확인할 것

| 확인 | 이유 |
| --- | --- |
| Visual Studio를 닫는다 | 켜져 있으면 `obj` 폴더가 생겨 컴파일이 깨진다 |
| NinjaScript Editor에서 F5를 눌러 에러가 없다 | 에러가 있으면 예전 코드로 백테스트가 돈다 |
| Connections에서 Playback 연결을 끊는다 | Playback에 연결된 동안에는 Run 버튼이 눌리지 않는다 |

## 2. 백테스트 절차

1. Control Center → New → **Strategy Analyzer**.
2. 종류는 **Backtest**, 전략은 **TQ_Strategy**.
3. **Instrument**: `MNQ DEC26`. 직접 입력하고 Enter.
4. **Data Series**: Type은 Minute, Value는 **3**. 여기가 진입 봉이다 (4장 참고).
5. **기간 (From / To)**: To는 마지막으로 보고 싶은 저녁의 **이틀 뒤 날짜**로 넣는다. 대회 시간이 자정을 넘기 때문이다. 예: 10/5 저녁까지 보려면 To = 10/7.
6. 아래 설정값을 확인하고 **Run**.
7. 결과에서 **Summary**(합계)와 **Trades**(거래 목록)를 본다.
8. Trades 탭에서 우클릭 → **Export**로 저장한다. 문서 폴더에 저장하고 Claude에게 "결과 봐줘"라고 하면 거래 단위로 분석한다.

### 지켜야 할 것

- **한 번에 하나만 바꾼다.** 두 개를 같이 바꾸면 어느 쪽 효과인지 알 수 없다.
- **바꾸기 전에 기본값으로 한 번 돌려 기준을 잡는다.** 같은 기간, 같은 봉으로 비교한다.
- **지금 가진 데이터는 9/29~10/5뿐이다.** 기간을 그보다 넓게 넣어도 결과는 같다.
- **결과가 좋아졌다고 바로 믿지 않는다.** 진입이 10번도 안 되는 표본이다.

## 3. 결과 읽는 법

NinjaTrader는 분할 진입 한 덩어리를 거래 1건으로 센다. 30계약을 6 / 12 / 12로 나눠 들어가면 3건이다. 같은 시각에 들어간 건들을 묶어 "진입 1번"으로 읽는다.

| Trades의 Entry name | 뜻 |
| --- | --- |
| UpL1, UpL2, UpL3 | 상승추세 매수 (주력). 6 / 12 / 12계약 |
| UpS1, UpS2 | 상승추세 매도 (역추세). 15 / 15계약 |
| DnL1, DnL2 | 하락추세 매수 (역추세). 10 / 20계약 |
| DnS1, DnS2, DnS3 | 하락추세 매도 (주력). 10 / 10 / 10계약 |
| SideL1, SideL2 | 횡보 매수. 15 / 15계약 |
| SideS1, SideS2 | 횡보 매도. 15 / 15계약 |

| Trades의 Exit name | 뜻 |
| --- | --- |
| x로 시작 (예: xSideL1) | 분할 익절 |
| Stop loss | 손절. 체결가가 진입가와 같으면 본절 |
| Sell / Buy to cover | 나머지 전량 청산 (청산 조건 충족 또는 00:27 종료 청산) |

| 열 | 뜻 |
| --- | --- |
| MAE | 보유 중 가장 불리했던 폭 (달러) |
| MFE | 보유 중 가장 유리했던 폭 (달러) |
| Bars | 보유한 봉 수 |

MNQ는 1포인트가 계약당 2달러다. 30계약이면 1포인트에 60달러.

## 4. 진입 봉 (Data Series)

전략은 여기서 고른 봉을 그대로 진입 봉으로 쓴다. 명세(v2)는 **1분봉**이다. 코드에 고정된 것은 추세 판단용 10분봉(과 `RegimeBarMinutes` 3일 때 쓰는 3분봉)뿐이다.

| | 1분봉 (명세) | 3분봉 |
| --- | --- | --- |
| 밴드 중심선 EMA 26봉 | 26분 | 78분 |
| ATR 14봉 | 14분 | 42분 |
| 전저점·전고점 5봉 | 5분 | 15분 |
| 반전 대기 6봉 | 6분 | 18분 |
| 마지막 조각 18선 | 18분 | 54분 |
| 추세 판단 | 10분봉 | 10분봉 (같음) |

## 5. 설정값

기본값은 `docs/spec.md` 8장과 같다(2026-10-12, 대면회의 이후 규칙). 실거래·대회 세팅은 `docs/contest-setup.md`를 본다.

설정창은 기능별 묶음(0. 화면·기록·테스트, 1. 진입 — 상승추세·하락 전환 의심, 2. 진입 — 하락추세·상승 전환 의심, 3. 진입 — 횡보, 4. 진입 — 공통, 5. 추세 판단, 6. 손절·본절, 7. 청산, 8. 수량·대회 시간, 9. 지표 계산값)으로 나뉘고, 각 항목은 "한국어 설명 (코드 이름)"으로 보인다. 이 문서의 표는 괄호 안의 코드 이름을 쓴다. 한 번에 하나만 바꿔 기준과 비교한다.

### 5-1. 진입 밴드 (묶음 1~3)

밴드 값은 0~3이고 0은 중심선이다. 규칙 번호는 spec 5장 표의 번호다.

| 설정값 | 기본 | 뜻 | 볼 것 |
| --- | --- | --- | --- |
| **UpLongBand** | 1 | 5.1 상승추세 매수: 저가가 몇 배 밴드에 닿으면 | 0. −1배까지 눌리지 않는 상승에서 진입이 나오는지 |
| **UpSusShortBand** | 1 | 5.3 하락 전환 의심 매도: 고가가 몇 배 밴드에 닿으면 | 2. 반등을 더 기다렸다 매도 |
| **UpSusLongBand** | 2 | 5.2 하락 전환 의심 매수: 종가가 몇 배 밴드 아래면 | |
| **DnShortBand** | 1 | 5.4 하락추세 매도: 고가가 몇 배 밴드에 닿으면 | 0, 2 |
| **DnLongBand** / **DnLongRsi** | 3 / 30 | 5.5 하락추세 매수(역추세): 저가가 몇 배 밴드에 닿고 RSI가 이 값 미만이면 | |
| **DnSusLongBand** | 1 | 5.6 상승 전환 의심 매수: 저가가 몇 배 밴드에 닿으면 | |
| **DnSusShortBand** | 2 | 5.7 상승 전환 의심 매도: 종가가 몇 배 밴드 위면 | |
| **SideBand** | 2 | 5.8·5.9 횡보: 저가(고가)가 몇 배 밴드에 닿으면 | |
| **T1WindowUp / T1WindowDn / T1WindowSide** | 0 | 5.1~5.3 / 5.4~5.7 / 5.8·5.9의 반전 신호 대기 봉 수. 0이면 공통값 `T1Window` | |

### 5-2. 진입 공통 (묶음 4)

| 설정값 | 기본 | 뜻 | 볼 것 |
| --- | --- | --- | --- |
| **T1Window** | 5 | 밴드 조건 뒤 반전 신호를 기다리는 봉 수. 실제 대기는 이 값 + (MacdConfirmBars − 1), 기본이면 6봉 | 늘리면 진입이 늘지만 밴드에서 멀어진 신호도 받는다 |
| **T1SameBar** | 켬 | 밴드에 닿은 그 봉에서 반전 신호가 같이 나오면 바로 진입. 끄면 다음 봉부터의 신호만 센다 | 끔과 비교해 진입 횟수와 진입 가격 |
| **UseCounterTrend** | 켬 | 5.5 하락추세 매수를 할지 | 끔. 급락하는 날의 손익 |
| **CounterQtyPercent** | 100 | 5.5의 수량 비율 | 50 |
| **BlockReentryAfterStop** | 켬 | 주력 진입(5.1, 5.4)이 아닌 진입이 손실로 손절되면 그 대회 구간에서 같은 방향의 주력 아닌 진입을 다시 하지 않는다 | 끔. 연속 손절이 나는지 |
| **KeepWaitOnTrendChange** | 켬 | 반전 신호를 기다리는 중에 추세가 바뀌면 그 대기를 새 추세의 같은 방향 규칙으로 이어 간다. 하락추세 매수(역추세)로는 이어 가지 않는다 | 로그의 "반전 신호 대기를 이어받음". 끔과 진입 횟수 비교 |
| **SkipEntryPastTarget** | 켬 | 신호 봉 종가가 그 규칙의 첫 익절 밴드를 이미 넘었으면 진입하지 않는다 | 로그의 "진입 보류" 횟수. 끄면 그 진입들이 어떻게 끝나는지 |
| **TrendT2Entry** | 끔 | 켜면 5.1·5.4도 밴드 조건 없이 MACD 전환 + 크로스가 같이 나올 때 진입 | 추세 구간 진입 횟수 |
| **T2CountConfirmBars** | 켬 | "MACD 전환 + 크로스" 조건에서 MACD가 실제로 꺾인 봉의 크로스도 인정. 진입과 청산 모두에 적용 | |
| **MacdConfirmBars** | 2 | 진입 봉의 MACD 히스토그램이 몇 봉 연속 늘어야(줄어야) 전환으로 볼지 | 1이면 전환이 매우 잦다 |
| **MacdMinChangeAtr** | 0 | 전환으로 인정할 최소 변화폭(ATR 배수). 0이면 사용 안 함 | 0.02~0.05 |

### 5-3. 추세 판단 (묶음 5)

추세는 "이동평균 배열 AND MACD선 부호"로 상승·하락을 정하고, 그 안에서 의심 조건이 뜨면 전환 의심이 된다 (spec 3장). 차트 배경색(`ShowStatus`)과 로그의 "10분봉 마감 추세=" 줄로 구간을 본다.

| 설정값 | 기본 | 뜻 | 볼 것 |
| --- | --- | --- | --- |
| **RegimeNoSideways** | 끔 | 켜면 횡보 없이 상승·하락추세와 각각의 전환 의심만 쓴다. 추세 조건이 둘 다 아닌 구간은 마지막 추세의 전환 의심이 된다. 횡보 매수·매도(5.8·5.9)는 나오지 않는다 | 켬. 횡보였던 구간에서 의심 규칙이 어떻게 동작하는지 |
| **RegimeMode** | 1 | 추세 판단 방식. 1 = 회의 문서 정의(정배열 + MACD선 부호), 2 = 점수 방식(가격·MACD 히스토그램·RSI·스토캐스틱 네 가지의 합, spec 3장). **2는 검증 전** | 같은 날을 1과 2로 돌려 추세 전환 시각 비교. 로그의 "분봉 마감 추세=… 점수=" 줄 |
| **RegimeScoreMin** / **RegimeScoreRsiBand** | 2 / 5 | 점수 방식에서 추세로 인정할 최소 점수 / RSI를 방향으로 세는 폭(5면 55 이상, 45 이하) | 최소 점수 3(늦지만 확실) |
| **RegimeBarMinutes** | 10 | 추세를 판단하는 봉. 3이면 3분봉. 아래 봉 수는 모두 이 봉 기준 | |
| **RegimeFast / RegimeMid / RegimeSlow** | 6 / 18 / 36 | 정배열·역배열을 보는 이동평균. 10분봉이면 1 / 3 / 6시간 | |
| **RegimeRsiHigh / RegimeRsiLow** | 60 / 40 | 하락 전환 의심은 RSI가 60 이상, 상승 전환 의심은 40 이하일 때만 | 의심이 너무 자주·드물게 뜨는지 |
| **RegimeRsiBars** | 3 | 의심의 RSI 조건을 최근 몇 봉 안에서 볼지. 1이면 같은 봉에서만 | 1과 비교. 고점 뒤 의심이 뜨는 시각 |
| **RegimeDivBars** | 15 | 다이버전스: 최근 몇 봉 안의 고점·저점과 비교할지 | |
| **RegimePivotStrength** | 2 | 좌우로 몇 봉보다 높아야(낮아야) 고점(저점)으로 볼지 | 3. 큰 고점만 인정 |
| **RegimeHistBars** | 2 | 추세 봉의 MACD 히스토그램이 몇 봉 연속 줄어야(늘어야) 전환으로 볼지 | |
| **SuspectReturn** | 켬 | 의심 중 반대 신호(히스토그램 연속 반전, 크로스)가 나오면 원래 추세로 돌아간다. 끄면 배열이나 MACD선 부호가 깨질 때까지 의심으로 남는다 | **켬과 끔 비교가 숙제다** (spec 9장) |

`RegimeSlow`만큼 추세 봉이 쌓이기 전에는 전략이 아무것도 하지 않는다. 기본값이면 6시간치가 먼저 필요하다.

### 5-4. 손절·본절 (묶음 6)

| 설정값 | 기본 | 뜻 | 볼 것 |
| --- | --- | --- | --- |
| **StopPercent** | 0.2 | 손절 % | |
| **UseSwingStop** | 켬 | 끄면 전저점·전고점을 쓰지 않고 `StopPercent`만으로 손절 | |
| **StopWider** | 켬 | 전저점·전고점과 % 중 진입가에서 먼 쪽을 손절가로. 끄면 가까운 쪽(v1) | 끔. 손실 한 번의 크기와 손절 횟수 |

| **TrailStopAtTp2** | 켬 | 두 번째 밴드 익절이 체결되면 손절을 첫 번째 익절 체결가로 옮긴다 | 끔과 비교. 로그의 "손절 이동 → … (1차 익절가)" 뒤 손절로 끝나는 거래가 많은지 |
| **BreakevenAtR** | 0 | 1차 익절 전이라도 이익이 처음 손절 거리의 이 배수에 닿으면 손절을 평단으로. 주력 진입 제외. 0이면 사용 안 함 | 1 |
| **BreakevenBufferTicks** | 8 | 손절을 옮길 때 현재 호가가 그 가격에서 이 틱 수 이상 떨어져 있어야 한다. 가까우면 미뤘다가 봉 마감마다 다시 시도 | 로그의 "손절 이동 대기"가 얼마나 자주 나오는지 |
| **HandleOrderErrors** | 켬 | 주문이 거부돼도 전략이 꺼지지 않고 직접 대처한다 (`docs/contest-setup.md` 7장) | |

순수하게 ATR만으로 손절하려면 `StopPercent`를 0으로 두고 `MinStopAtr`에 배수를 넣는다.

### 5-6. 지표 (묶음 9, 건드릴 일이 거의 없음)

진입 봉과 추세 봉에 같은 값을 쓴다.

| 설정값 | 기본 | 뜻 |
| --- | --- | --- |
| BandMidPeriod / BandAtrPeriod | 26 / 14 | ATR 채널의 중심선 EMA 기간과 ATR 기간 |
| BandMult1 / 2 / 3 | 1 / 2 / 3 | 밴드 배수 |
| MacdFast / MacdSlow / MacdSmooth | 12 / 26 / 9 | MACD |

## 8. 자주 겪는 문제

| 증상 | 원인과 해결 |
| --- | --- |
| Run 버튼이 눌리지 않는다 | Playback에 연결돼 있다. 연결을 끊는다. 종목이 비어 있어도 안 눌린다 |
| 거래가 0건이다 | 그 기간의 데이터가 없다. 종목과 기간을 확인한다 |
| 결과가 지난번과 전혀 다르다 | Data Series의 Value(1인지 3인지), 기간의 To 날짜를 확인한다 |
| `TargetFrameworkAttribute` 중복 에러 | Visual Studio가 `obj` 폴더를 만들었다. 폴더를 지우고 Visual Studio를 닫는다 |
| 설정값을 바꿨는데 차트의 지표가 그대로다 | 차트에 올려둔 지표는 예전 설정을 기억한다. 지웠다가 다시 올린다 |

## 9. 학습 데이터 쌓기 (`MlLogToFile`)

`MlLogToFile`(기본 켬)이 켜져 있으면 거래가 끝날 때마다 `내 문서\NinjaTrader 8\TQ_ml_종목.csv`에 한 줄이 쌓인다(예: `TQ_ml_MNQ.csv`). Strategy Analyzer 백테스트에서도 쌓이므로, 기간이나 설정을 바꿔 돌릴 때마다 데이터가 늘어난다. 매매 판단에는 영향이 없다. 머신러닝으로 "어떤 신호가 손절로 끝나는지"를 분석하는 데 쓴다.

- 한 줄 = 거래 1건(분할 진입 한 덩어리). 왼쪽은 **진입 신호 봉에서 잰 특징값**, 오른쪽은 **그 거래의 결과**다.
- `#`으로 시작하는 줄은 실행별 설정 요약이다. pandas에서는 `pd.read_csv(path, comment='#')`로 읽는다.
- **같은 구간을 여러 번 돌리면 같은 거래가 중복으로 쌓인다.** 분석할 때 `signal_time`·`instrument`·`settings_id`가 같은 줄은 하나만 남긴다. 차트에 전략을 켤 때도 과거 구간 거래가 다시 쌓인다(`mode` = `hist`).
- **최적화(Optimize)를 돌릴 때는 끈다.** 설정 조합마다 줄이 쌓이고, 동시에 쓰다가 일부 줄이 빠질 수 있다.
- 파일을 처음부터 다시 모으려면 파일을 지우거나 이름을 바꾼다. 다음 실행 때 머리글부터 새로 쓴다.
