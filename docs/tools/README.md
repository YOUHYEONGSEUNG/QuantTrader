# 추세 판단 채점기 (`tq_regime_score.py`)

추세 판단 방식이 큰 움직임을 얼마나 빨리, 얼마나 정확하게 잡는지 숫자로 비교하는 도구다. NinjaTrader 밖에서 돌아서 백테스트 한 번 돌릴 시간에 여러 설정을 비교할 수 있다. 매매 규칙(spec)은 바꾸지 않는다.

## 하는 일

1. **추세 판단 재현:** 1분봉으로 3분·10분봉을 만들고 `TQ_Regime.cs`의 판정(방식 1·2, 전환 의심, 다이버전스, 추가 옵션)을 그대로 계산한다. MACD·RSI·ATR은 NinjaTrader 내장 지표와 같은 식이다. 1분봉 마감 때는 그보다 먼저 마감된 추세 봉의 값을 쓴다 (spec 3장 1봉 지연).
2. **사후 정답:** 1분봉 종가 지그재그로 한 방향 움직임(다리)을 나눈다. 반대로 10분봉 ATR(14) × 1.5 이상 되돌리면 다리가 끝나고, 대회 시간 안에서 크기가 ATR × 3 이상인 다리를 추세로 본다.
3. **채점 항목**

| 항목 | 뜻 |
| --- | --- |
| 잡은 다리 | 정답 추세 중 그 방향으로 판정한 적이 있는 수 |
| 지연 | 다리가 시작되고 그 방향 추세로 처음 판정하기까지 걸린 분 |
| 잡은 뒤 남은 몫 | 판정한 시점부터 다리 끝까지 남은 움직임 ÷ 다리 크기 (놓친 다리는 0) |
| 따라가기 | 진입 시간대에 판정이 바뀐 1분봉 종가에 들어가고, 판정이 바뀌거나 종료 시각에 나온 포인트. 1계약, 익절·손절·수수료 없음 |
| 분 정확도 | 대회 시간의 1분마다 판정 방향이 정답과 같은 비율. "추세라 한 분 중 맞음"은 정밀도, "추세 분 중 잡음"은 재현율 |

방식마다 두 가지로 본다. **추세만**은 ±2만 방향으로 보고, **유기 방향**은 하락 전환 의심을 매도, 상승 전환 의심을 매수로 본다 (spec 5-2).

## 준비

- Python 3 (표준 라이브러리만 씀). Windows는 `py`로 실행한다.
- 1분봉 데이터: Control Center → Tools → Historical Data → Export. 종목(예: MNQ 09-26), Last, Minute, 기간은 채점할 첫날보다 최소 3일 앞부터. 내보낸 파일은 `yyyyMMdd HHmmss;시가;고가;저가;종가;거래량` 형식이고 시각은 항상 UTC라서 채점기가 KST(+9)로 바꾼다.

## 실행

```
py docs/tools/tq_regime_score.py --data "C:\Users\user\Desktop\Ninja_Exports\MNQ 09-26.txt"
```

설정을 주지 않으면 다섯 가지를 비교한다: 문서 정의 10분·3분, 점수 10분·3분, 유기 기준 세트(점수 3분 + RSI 상대 26/6).

| 옵션 | 기본값 | 뜻 |
| --- | --- | --- |
| `--data 파일...` | | 내보낸 1분봉. 여러 개면 합친다 |
| `--cfg "이름:설정"` | | 비교할 설정. 여러 번 쓸 수 있다. 예: `--cfg "점수3분 최소3:mode=2,bar=3,scoremin=3"` |
| `--validate 로그` | | `TQ_log_종목.txt`의 "N분봉 마감 추세=… MACD선=… RSI=… 점수=" 줄과 재현값 비교 |
| `--contract SEP26` | | 검증할 계약월 |
| `--start` / `--entry-end` / `--flatten` / `--end` | 2130 / 2315 / 2327 / 2330 | 대회 시작, 진입 마감, 종료 청산, 채점 끝 (KST, HHMM) |
| `--all-hours` | | 대회 시간 대신 하루 전체를 채점 |
| `--rev-atr` / `--trend-atr` / `--atr-bar` | 1.5 / 3 / 10 | 정답 기준: 되돌림 배수, 추세 크기 배수, ATR 봉 |
| `--report 파일.md` | | 결과 표를 마크다운으로 저장 |

**대회 시간 기본값은 21:30~23:30이다** (spec 7장, 2026-10-14 확정). 예전 대회 시간(22:30~00:30)으로 보려면 `--start 2230 --entry-end 15 --flatten 27 --end 30`을 준다.

`--cfg`에서 쓸 수 있는 설정 (TQ_Regime 설정값과 같은 뜻, 기본값은 spec 8장)

| 이름 | 기본 | 이름 | 기본 |
| --- | --- | --- | --- |
| `mode` | 1 | `bar` (추세 봉 분) | 10 |
| `fast` / `mid` / `slow` | 6 / 18 / 36 | `hist_bars` | 2 |
| `rsi_high` / `rsi_low` | 60 / 40 | `div_bars` / `pivot` | 15 / 2 |
| `scoremin` / `exit` / `band` / `event` | 2 / 0 / 5 / 3 | `rsibars` | 1 |
| `rsirel` / `center` / `offset` | 0 / 20 / 8 | `return` (SuspectReturn) | 1 |
| `nosideways` / `needsprice` | 0 / 0 | MACD·스토캐스틱·크로스 | spec 기본값 |
| `maxscore` (SuspectMaxScore) | 5 | `evidence` / `evbars` (SuspectMinEvidence / SuspectEvidenceBars) | 1 / 2 |
| `confirm` / `exitbars` (TrendConfirmBars / TrendExitBars) | 1 / 1 | | |

`maxscore`·`evidence`·`evbars`·`confirm`·`exitbars`는 2026-10-14에 TQ_Regime과 같이 넣었다(spec 3-1). 그날은 Python이 없는 PC에서 고쳐서 실행해 보지 못했다. 기본값이면 그 전과 같은 값을 낸다. 설정을 주지 않으면 비교하는 기본 목록에 10/14 유기 기준 세트(점수 3분 + RSI 상대 14/6 + 의심 점수 상한 2)를 더했다.

## v3 (mode=3) — 2026-10-15 추가

`mode=3`은 TQ_Regime v3(spec v3 3장)와 같은 식이다(`compute_regime_v3`). 느린 점수 S·빠른 점수 F로 추세 +1 / 0 / −1을 내고, 의심은 이벤트로만 낸다. 다른 방식과 같이 채점하려고 추세 값은 +2 / 0 / −2로 돌려준다.

| 이름 | 기본 | 뜻 |
| --- | --- | --- |
| `fast` / `mid` / `slow` | (v3 비교에서는 6 / 20 / 60을 직접 줌) | 단기 / 중기 / 장기 SMA |
| `s2` (S2 방식) / `slope` | 1 / 5 | 1 = 중기 > 장기, 2 = 장기선이 slope봉 전보다 높음 |
| `userrsi` / `band` | 1 / 5 | S4 RSI 항목 사용 / 폭 |
| `mslope` | 2 | F2 MACD선 연속 봉 수 |
| `tsf` / `tss` / `tes` / `sf` | 2 / 2 / 0 / 2 | 추세 시작 F / 시작 S / 종료 S / 의심 F |

v3 지시서 3-4의 비교 목록을 한 번에 돌리려면 `--v3`를 준다 (mode=2 10분, mode=2 3분 유기 기준, mode=3 3분 {Fast 6/8} × {S2 1/2} × {RSI 켬/끔}):

```
py docs/tools/tq_regime_score.py --data "9월 1분봉.txt" --v3 --report v3_sep.md
py docs/tools/tq_regime_score.py --data "10월 1분봉.txt" --v3 --report v3_oct.md
```

표에 의심 이벤트 열이 더해졌다: 이벤트 수, 이벤트 뒤 30분 동안 의심 방향 최대 폭이 반대 방향 최대 폭보다 컸던 비율, 두 폭의 평균. mode 1·2는 의심 상태로 들어간 봉을 이벤트로 센다.

`--validate`는 v3 전략 로그(`TQ_log_v3_종목.txt`, 실행 머리줄 `버전=v3`)의 추세 봉 줄도 읽는다. 표의 "배열" 칸은 S, "점수" 칸은 F로 비교한다.

## 진입 규칙 비교 시뮬레이터 (`tq_entry_sim.py`) — 2026-10-15 추가

전략 로그(`TQ_log_v3_종목.txt` 또는 `TQ_log_v4_종목.txt`)의 진입 봉 줄(1분봉 시고저종)과 추세 봉 줄(3분봉 S·F·이평)을 읽어, 진입 규칙만 바꿔 가며 v3 추세 포지션 청산 규칙(손절, 1·2차 밴드 익절, 이미 지난 밴드, 1차 뒤 손절, 이익 보호 0.8R, 트레일링, 의심 일부청산, 마지막 조각, 종료 청산)으로 거래를 재현한다. 1분봉 내보내기가 없는 날도 Playback 로그만 있으면 된다.

```
py docs/tools/tq_entry_sim.py --log "C:\Users\…\Documents\NinjaTrader 8\TQ_log_v3_MNQ.txt" --dates 2026-07-15,2026-07-16 --report out.md
```

- 비교하는 규칙: v3 E1+E3(로그의 추세 판정), E3만, 돌파 N봉 × F 기준 × S 거르기, 2봉 확인, 거리 제한, 장전 박스 + 돌파.
- 날마다 그날 23:27까지 간 실행 중 봉이 가장 많은 것을 쓴다. 봉 안 순서는 손절 먼저, 체결 미끄러짐 0.5pt, 장전 수량 50%.
- **한계:** Playback보다 낙관적이다(부분 체결 없음). 1분 EMA·ATR은 로그 첫 봉(21:2x)부터 쌓아 21:35 무렵은 실제와 조금 다르다. E2(1분 T1 대기)와 E4는 재현하지 않는다.

## 한계

- 정답 기준(되돌림 1.5, 크기 3)은 임의로 정한 값이다. 트레이더가 보는 추세와 맞는지 확인해야 한다.
- "따라가기"는 판정만 따라간 결과라 전략의 실제 손익(밴드 진입, 분할 익절, 손절)과 다르다. 판정 방식끼리 비교하는 용도다.
- 데이터 앞부분 2~3일은 지표가 쌓이는 구간이라 NinjaTrader 값과 조금 다를 수 있다.
- 전략 코드의 추세 판정이 바뀌면 이 파일의 `compute_regime`도 같이 고친다.
